# Créer l'équipe et attribuer les accès

Se connecter à l'espace réel avec le compte super administrateur. Les données de démonstration sont fictives : le bouton « Quitter la démo et me connecter » permet de revenir à la connexion.

## Création directe

Équipe → Créer un compte → nom et prénom → e-mail → rôle (Collaborateur ou Responsable) → Créer et activer. Le code aléatoire s'affiche une seule fois. Le transmettre à la personne par un canal privé. Le mot de passe n'est pas conservé sous forme lisible.

## Inscription par invitation

Équipe → Créer un lien d'inscription. Le lien est individuel, valable 48 heures et utilisable une seule fois. La personne fournit son nom et son e-mail, puis attend l'autorisation. Sur sa fiche : Activer et générer le code.

## Modifier un rôle ou un accès

Sur la fiche d'un membre : Rôle & accès. Le super administrateur peut choisir Collaborateur ou Responsable. Décocher « Autoriser l'accès à l'application » suspend le compte sans supprimer ses tâches ni son historique. Le serveur refuse les opérations métier d'un compte inactif. Le compte Auth est également bloqué pour les nouvelles connexions.

« Générer un nouveau code » réinitialise l'accès et affiche le nouveau code une seule fois. Ne jamais le publier sur GitHub ou dans un document partagé.

## Déléguer au responsable

Modules & paramètres → Invitations par le manager pour les liens d'inscription ; Gestion des accès par le manager pour créer, activer ou réinitialiser les comptes collaborateurs. Ces modules sont indépendants. Un manager ne peut pas se promouvoir, modifier un autre responsable ni donner un rôle de super administrateur.

## Accès au lien de l'application

Le lien du site doit aussi être accessible aux collaborateurs au niveau de l'hébergement. Créer un compte métier ne modifie pas le partage du site privé dans ChatGPT. Les permissions d'hébergement et les rôles dans l'application sont distincts.
